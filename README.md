# Photo Yandex Bot V2

Telegram Serverless + Google Sheets + Яндекс Диск. В личном чате одна кнопка «📋 Заполнить таблицу». Бейдж → имя → фамилия → одна фотография. Фото записывается в отдельную папку Диска под именем бейджа, публикуется; таблица получает имя, фамилию, бейдж, публичную ссылку. Повторный бейдж обновляет строку и заменяет фото. Бейджи чувствительны к регистру; ведущие нули сохраняются. /cancel отменяет незавершённый ввод, /retry повторяет неудачное сохранение, /id показывает ID. Только разрешённые пользователи.

## Настройка

1. В BotFather включить Serverless, получить новый CLI-токен (Serverless → CLI Access). Старый Python polling остановить перед деплоем.
2. В Google Cloud включить Sheets API, создать OAuth client. Получить refresh token с разрешением https://www.googleapis.com/auth/spreadsheets (offline access). Можно использовать OAuth Playground с собственными OAuth credentials и разрешённым redirect URI https://developers.google.com/oauthplayground; для долговременной работы не оставлять внешнее приложение в статусе Testing (токены могут истекать через 7 дней).
3. Создать Google Таблицу и лист «Сотрудники» или указать другое имя существующего листа. Аккаунту OAuth нужен доступ редактора. Заголовки A1:D1: Имя | Фамилия | Бейдж | Ссылка на файл. Пустой лист бот заполнит заголовками; существующие заголовки проверяются. Столбец C лучше заранее отформатировать как обычный текст.
4. Получить новый OAuth-токен Яндекс Диска с правом создания, загрузки, публикации и чтения файлов. По умолчанию disk:/EmployeePhotos; для токена с доступом только к папке приложения используйте app:/EmployeePhotos.
5. GitHub → Settings → Secrets and variables → Actions. Добавить TGCLOUD_TOKEN и BOT_CONFIG_JSON. В BOT_CONFIG_JSON положить JSON следующего вида (заменить все значения):

```json
{"allowedUserIds":[123456789],"yandexToken":"NEW_TOKEN","yandexRoot":"disk:/EmployeePhotos","googleClientId":"CLIENT_ID","googleClientSecret":"CLIENT_SECRET","googleRefreshToken":"REFRESH_TOKEN","spreadsheetId":"SPREADSHEET_ID","sheetName":"Сотрудники"}
```

Секреты генерируют серверный модуль только на CI runner; не коммитить получившийся config.js. Доступ к Serverless CLI и Actions должен быть ограничен. Не использовать ранее опубликованные токены; отозвать их, перевыпустить OAuth secret и токен бота. Удаление файлов не очищает git history.

6. Actions → Check and deploy Serverless → Run workflow → v2-serverless (для теста). После проверки можно объединить ветку с main; далее деплой по push в main. Команды: tgcloud push, tgcloud migrate --safe, tgcloud webhook sync.

## Проверка
npm test. В реальном боте проверить доступ, /start, новый бейдж, повторный бейдж, сбой Sheets и /retry. Убедиться, что ссылка открывается без авторизации и ведёт к нужному фото. Публичная ссылка даёт просмотр любому, кто её получил, и может позволять скачивание; не публиковать фото без согласия/основания. Таблицу оставлять закрытой. Бот не удаляет фото при частичной ошибке между Диском и Sheets; повторная попытка использует тот же путь. Внешние API не образуют единой транзакции. Не редактировать строки параллельно с сохранением ботом. При дублированных бейджах исправить таблицу вручную. Поддерживается только одно обычное Telegram-фото (не альбом/документ). Старый Python код оставлен в main.
